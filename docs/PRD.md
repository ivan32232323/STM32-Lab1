# PRD — Motion-Mirroring Teleoperator

**Версія:** 1.0 (ЛР1) · **Платформа:** Nucleo-C031C6 / Wokwi (цільова реальна: Nucleo-F446RE) · **Виконавець:** індивідуально

## A. Загальна ідея

Пристрій «дзеркалить» рух руки оператора на двовісний маніпулятор. На кисті закріплено IMU MPU-6050.
Мікроконтролер обчислює нахил кисті (roll → pan, pitch → tilt) і в реальному часі повертає два
сервоприводи на ті самі кути. Кнопка перемикає режими: ручне керування потенціометром, дзеркалення,
а далі запис траєкторії та її автономне відтворення.

**Для кого:** навчальна модель систем телеприсутності: дистанційні маніпулятори для небезпечних
середовищ (ліквідація аварій, розмінування), роботизована реабілітація кисті, motion-capture
для анімації. Комерційні аналоги: master-slave консолі хірургічних роботів (Intuitive da Vinci),
рукавички-контролери (Manus, SenseGlove). Наш пристрій показує ключові інженерні задачі цього класу:
sensor fusion, жорсткий дедлайн керування, вимірювану end-to-end латентність і безпечну поведінку
при втраті сенсора.

## B. Функціональні вимоги

| ID | Вимога | Пріоритет | Датчик / вузол |
|---|---|---|---|
| FR-01 | Система повинна визначати roll і pitch кисті в діапазоні ±90° з похибкою ≤ 3° у статиці. | Must | MPU-6050 (I²C) |
| FR-02 | Система повинна повертати серво pan/tilt на кут, що відповідає roll/pitch, з дискретністю ≤ 1°. | Must | SG90 ×2 (PWM) |
| FR-03 | End-to-end латентність «рух IMU → оновлення PWM» повинна бути < 50 мс (ціль ≤ 25 мс). | Must | MPU-6050 + TIM3 |
| FR-04 | Контур керування повинен виконуватися з частотою ≥ 50 Гц, а fusion-задача — вкладатися в 5 мс. | Must | MCU |
| FR-05 | У режимі MANUAL кут pan повинен задаватися потенціометром лінійно (0…4095 → −90…+90°). | Must | Потенціометр (ADC) |
| FR-06 | Система повинна мати мертву зону ±2° і обмеження швидкості серво ≤ 300 °/с, щоб гасити тремтіння руки. | Should | ПЗ |
| FR-07 | Кнопка MODE повинна циклічно перемикати режими MANUAL → MIRROR (→ RECORD → PLAYBACK у ЛР2+) з антидребезгом 20 мс. | Must | Кнопка (GPIO) |
| FR-08 | Під час старту система повинна виконати самодіагностику (HAL init, I²C-scan, WHO_AM_I = 0x68) і вивести звіт в UART. | Must | UART, I²C |
| FR-09 | Якщо IMU не відповідає > 100 мс, система повинна перевести серво в нейтраль (1.5 мс), увімкнути індикацію LD4 і повідомити в UART. | Must | MPU-6050, LED |
| FR-10 | Щосекунди система повинна виводити телеметрію: режим, кути, сире значення ADC, ширину імпульсів PWM. | Should | UART |
| FR-11 | У режимі RECORD траєкторія повинна записуватися ≥ 30 с з частотою 50 Гц і відтворюватися в PLAYBACK. Сховище — W25Q64 на реальній платі, RAM-буфер у Wokwi. | Could (ЛР3) | SPI-flash |

## C. Список датчиків

### MPU-6050 (InvenSense, модуль GY-521) — I²C @0x68
* **Навіщо:** єдине джерело орієнтації кисті. Реалізує FR-01, FR-03, FR-09. Гіроскоп потрібен
  для комплементарного / Mahony-фільтра у ЛР2: акселерометр сам по собі шумить при русі.
* **Альтернативи:**
  * *GY-89 (L3GD20 + LSM303D + BMP180)* — дає магнітометр для абсолютного азимуту (yaw), але три чипи
    на шині ускладнюють bring-up, і в Wokwi його немає. Залишаємо як розширення.
  * *ADXL345* — лише акселерометр, без гіроскопа, тож fusion неможливий.
  * *Аналоговий акселерометр ADXL335 (3×ADC)* — займає 3 канали ADC, без гіроскопа, шумний.

### Потенціометр 10 кОм — ADC1_IN0
* **Навіщо:** задавач положення в режимі MANUAL (FR-05) і калібрування нуля серво. Дає змогу
  перевірити PWM-тракт незалежно від IMU.
* **Альтернативи:** енкодер KY-040 (точніший, але потрібні EXTI і рахування фронтів, для ЛР1 зайве);
  джойстик (2×ADC) — надлишковий.

### Кнопка MODE — GPIO (PA10, pull-up)
* **Навіщо:** перемикання режимів (FR-07) без хоста.
* **Альтернативи:** команди через UART CLI (буде в ЛР2 як доповнення); сенсорна кнопка TTP223 — те саме
  GPIO, але дорожча.

### Виконавчі пристрої: серво SG90/SG92R ×2 — PWM TIM3_CH1/CH2
* **Навіщо:** «віддалена рука» (FR-02, FR-04, FR-06).
* **Альтернативи:** кроковий двигун 28BYJ-48 + ULN2003 точніший, але повільний і без абсолютної позиції;
  MG996R потужніший, але споживає > 1 А.

## D. План тестування

| Вимога | Тест | Інструмент | Критерій проходження |
|---|---|---|---|
| FR-01 | Задати в Wokwi нахил MPU-6050 (rotation X/Y) 0°, ±30°, ±60°, ±90° і зчитати pitch/roll з телеметрії. На залізі — порівняти з транспортиром. | Wokwi MPU-6050, UART | Похибка ≤ 3° |
| FR-02 | Для кутів −90…+90° з кроком 10° виміряти ширину імпульсу на D12/D11. | Wokwi Logic Analyzer / Saleae | 1000 ± 10 мкс … 2000 ± 10 мкс, лінійно |
| FR-03 | GPIO-toggle (PB0) у момент отримання нового зразка IMU і в момент запису CCR. Різниця фронтів — латентність. | Logic Analyzer | Медіана < 25 мс, максимум < 50 мс на 200 вимірах |
| FR-04 | Toggle піна на вході й виході контуру, виміряти період і тривалість. | Logic Analyzer | Період 20 ± 1 мс, тривалість fusion ≤ 5 мс |
| FR-05 | Крутити потенціометр 0 % → 50 % → 100 %, читати `pot` і `pwm1`. | UART | 0→1000 мкс, ~2048→1500 мкс, 4095→2000 мкс |
| FR-06 | Подати на вхід «тремтіння» ±1° (зміною кута в Wokwi) — серво не рухається. Ступінчастий стрибок 0→90°. | UART, LA | Зміна PWM = 0 при ±1°; час стрибка ≥ 300 мс |
| FR-07 | 20 натискань кнопки, рахувати перемикання в логу. | UART | Рівно 20 перемикань, жодного подвійного |
| FR-08 | Холодний старт. Окремий тест: відключити SDA від MPU-6050 у diagram.json. | UART | Повний звіт `[ OK ]`. Без IMU — `NOT FOUND`, система не зависає |
| FR-09 | Під час MIRROR від'єднати MPU (відключити VCC у Wokwi). | UART, LA | За ≤ 100 мс PWM = 1500 мкс, LD4 блимає, повідомлення в логу |
| FR-10 | Записати 60 с логу. | UART | 60 ± 1 рядків `tick`, усі поля присутні |
| FR-11 | Записати 30 с руху, вимкнути живлення (на залізі), відтворити. | UART, LA | Відтворена траєкторія збігається з записом ± 2° |

## E. Статус на кінець ЛР1

FR-08 і FR-10 реалізовано. FR-02, FR-05 і FR-07 реалізовано в базовому вигляді. FR-01 реалізовано
частково: кути лише з акселерометра, без фільтра. Решта — ЛР2–ЛР4.
